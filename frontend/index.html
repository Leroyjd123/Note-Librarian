What this tool does

It is made for JW Library personal study notes. Export your notes to an Excel file (.xlsx), upload it here, and an AI model makes them easier to find and read. For every note it can improve four things only - the title, the note text, the tags, and the colour. It matches those columns by their headers, so the export's column order doesn't matter. Everything else in your file (other columns, formatting, hyperlinks, other rows) is left exactly as it was, and a .bak backup of your original is saved automatically.

The settings, in plain words

Provider
Which AI company runs your notes - Claude (Anthropic), OpenAI, or Gemini (Google). You bring your own API key.
API key
A secret password-like string from your provider's website that lets the app use your account. You paste it in; it is used only to run your file and is never stored on the server.
Model ID
The exact name of the model to use, e.g. claude-sonnet-4-6, gpt-4o, gemini-1.5-pro. It picks which version/size of the AI is called. Larger models are usually more accurate but cost more and run slower. It must be a model your key has access to.
Mode
Full pass organises everything (titles, tags, colours, plus light grammar fixes). Notes only leaves titles/tags/colours untouched and just cleans the note wording.
Note level
Only for "Notes only" mode. Spelling/grammar = fix typos, keep your exact words. Grammar + clarity = also smooth awkward phrasing. Clarity + reconstruct = also gently rebuild unclear notes into their intended meaning (never adding new ideas).
Batch size
How many notes are sent to the AI in one request. Smaller batches are more reliable (less chance of a cut-off reply) but make more requests. ~40 is a good balance.
Concurrency
How many batches are processed at the same time. Higher is faster but can hit your provider's rate limits.
Max tokens
The maximum length of each AI reply. It must be large enough to hold all the results for one batch. If it is too small the reply gets cut off - the app detects this, splits the batch, and retries automatically.

How it handles each note

1. It classifies the note as one of: Note, Observation, Fact, Question, Reflection, Illustration, Outline, Research, Reference, Study-note, or Stub. Questions are kept as unanswered questions. Fragments it can't safely interpret are left untouched and flagged.

2. It writes a searchable title (20-70 characters, no scripture references) - but only when the existing title is missing, unclear, or just a verse phrase. Good titles are kept.

3. It assigns a colour by meaning:

1Research / Backgroundhistory, word/language study, customs, chronology, prophecy, doctrine
2Personal Reflectionself-examination - "Do we...", "Am I..."
3Teaching Pointa clear lesson - good for a talk, comment, or discussion
4General Observationthe default for most notes
5Warninga negative example, danger, failure, or consequence
6Illustrationthe value is the comparison or word-picture itself

When several fit, priority is 6 > 5 > 2 > 3 > 1 > 4. The colour already in your file is ignored (it is just an app highlight) and reassigned from the note's meaning.

4. It builds tags in layers: People/places (Bible names, nations, groups), then Topics (qualities, themes, ministry, family...), then Situations (grief, anxiety, persecution...), then Workflow (Question, Review, Study Note...). Old/short tags are retired or remapped (e.g. job → Job, WT → Watchtower, Ask → Question). It won't invent brand-new topic tags; if a useful new concept comes up it lists it under Pending tags for your approval instead of applying it.

5. It corrects note text conservatively. It never invents meaning, lessons, or interpretation; it preserves your voice and uncertainty words ("maybe", "perhaps"); and it leaves genuine Bible/publication quotes exactly as they are.

Confidence & safety

  • Confidence is HIGH, MEDIUM, or LOW. Anything MEDIUM or LOW is added to the Review list and tagged Review so you can check it.
  • Low-confidence notes are never rewritten - the original is kept.
  • Only TITLE, NOTE, TAGS, COLOR cells that actually change are written. Hyperlinks, styles, and every other cell stay byte-for-byte identical.
  • A .bak copy of your original workbook is created on the first write.
  • If the AI's reply for a batch can't be read, the app splits and retries; in the worst case it leaves a note unchanged (shown under Warnings) rather than risk corrupting it.
